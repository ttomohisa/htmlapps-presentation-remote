# Presentation Remote v1.1.0 design

Approved scope: reliable command-result display, a presentation timer, and square QR scan guides. No extra product features, dependencies, signaling services, persistence, merge, release, or production deployment.

## Chosen approaches

- Command completion is reported by the host after the operation (and navigation rendering), not inferred from periodic state or the existing receipt ACK. The phone shows pending, applied, or unconfirmed status. It never automatically resends. Results carry the client session/sequence and deck revision; duplicate commands do not execute twice. Older peers may still navigate but cannot falsely claim completion.
- The host owns the timer. It starts idle after opening a deck; explicit Start, Pause, Resume and Reset work on PC and phone. Optional whole-minute duration is 1–180 minutes, with no limit as the default. Both screens show elapsed, remaining or overtime, without stopping slides at zero. Reset returns to idle and preserves the chosen duration. Deck replacement resets elapsed/state; reload discards all timer state. Fullscreen has no timer side effects.
- Keep the camera video geometry and decoder unchanged. Center the square guide using the smaller displayed frame dimension, and update on resize/orientation changes. Correct both embedded CSS copies and the reusable component.

## Alternatives considered

State-inference completion cannot identify individual quick commands. Independent phone clocks drift across pause/reconnect. Cropping the camera viewport to square needlessly changes the visible camera area. None is selected.

## UX and compatibility

Keep primary navigation dominant. Add a small polite command-status line; keep expanded timer configuration in the PC session card / phone More panel. Do not announce ticking seconds in a live region. Do not overwrite an actively edited duration draft during state sync. Expose unavailable completion/timer support with older peers. Continue using protocol v4 with additive capability and result fields. Continuous pointer motion is not an acknowledged command.

## Verification

Test completion timing, failures, supersession, duplicates, deck changes, disconnects, late/foreign results and legacy peers. Test timer transitions, validation, pause interpolation, reconnect, reset, deadline crossing, and fullscreen independence. Test guide geometry at wide/portrait/landscape sizes and after resize without changing video pixels. Run all existing suites, build both standalone variants, browser-test synthetic decks and paired browsers, review independently, then create a draft PR and verify exact-head CI. Only synthetic files may be used for tests.
